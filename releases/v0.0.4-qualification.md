## Hold and recovery

Hold promotion for an inaccessible primary control, an incorrect task or approval mutation, or a failure that hides active work. Retain the pre-upgrade PostgreSQL backup, keys, and the previous compatible source. Apply the rehearsed managed Git rollback when the data schema permits it. Restore to a fresh target when needed. Verify membership and assignments, invite acceptance, approval state, and keyboard task movement before resuming operator work. Reconcile persisted mutations through task and approval history.

For a fresh-target restore, install the qualified source, provision an isolated compatible PostgreSQL database, and confirm its connection URL before running the restore. The native archive contains gzip-compressed SQL with cleanup statements. Point `FRESH_TARGET_DATABASE_URL` to the disposable, fresh target and `PROPRIO_BACKUP_ARCHIVE` to the retained native backup.

```bash
set -o pipefail
: "${FRESH_TARGET_DATABASE_URL:?set the fresh target URL}"
: "${PROPRIO_BACKUP_ARCHIVE:?set the native backup path}"
gzip -dc -- "$PROPRIO_BACKUP_ARCHIVE" |
  psql -X -v ON_ERROR_STOP=1 --dbname "$FRESH_TARGET_DATABASE_URL"
```

Check that the pipeline succeeded. Restore the matching signing and storage settings through the documented configuration. Verify PostgreSQL constraints and the selected company, task, and receipt records on the fresh target before cutover.
